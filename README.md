# DAI 2026 데이터 파이프라인 실습

서강대 "AI를 위한 데이터분석" 2026 가을 학기, 마지막 3회 실습 자료입니다.

## 3일 동안 무엇을 하나

### 상황

2001년, 여러분은 미국 에너지 회사 **엔론(Enron)** 의 천연가스 영업팀에 새로 왔습니다.
전임자 **Kim Ward**는 미국 서부의 시청·전력회사에 가스를 팔던 영업 담당입니다. 그가 남긴 것은 메일함 하나, **2,611통**입니다.
고객사와의 계약, 가격 제안, 공급 문제가 전부 이 안에 흩어져 있습니다.

3일 뒤의 목표는 이 메일함에 질문하면 **근거 메일과 함께 답해 주는 나만의 챗봇**입니다.

> **질문** Citizens Utilities가 Griffith 발전소 가스 공급 문제로 뭐라고 했지?
>
> **답** 2001년 11월 26일 Citizens의 Sean Breen이, Enron이 조치를 취하는 것을 확인했고 계속 지켜보겠다며
> 앞으로 공급이 끊기면 가장 먼저 자신에게 직접 알려 달라고 요청했습니다. (근거: `inbox/340`)

### 왜 바로 챗봇을 만들 수 없나

메일함 원본은 생각보다 지저분합니다.

- 메일 한 통에 사람이 쓴 글은 몇 줄뿐이고, 나머지는 기계가 붙인 머리말·면책 문구·이전 메일입니다. 어떤 메일은 365단어 중 48단어만 사람이 쓴 글입니다 ([Part 1](part1/)에서 직접 봅니다).
- 답장할 때마다 이전 메일이 딸려 오고, 같은 메일이 여러 폴더에 사본으로 들어 있어 같은 문장이 수십 번 나옵니다.
- 광고, 뉴스 알림, "ok" 한 단어짜리 메일이 섞여 있습니다.

이대로 챗봇에 넣으면 같은 문장을 열 번 찾아오거나 광고를 답으로 내놓습니다.
그래서 먼저 데이터를 다듬어야 합니다. 원본을 여러 단계에 걸쳐 쓸 수 있는 형태로 바꾸는 흐름을 **데이터 파이프라인**이라고 합니다.

### 3번의 수업 = 파이프라인의 3단계

```
원본 메일함 2,611통 ──▶ Part 1 정제 ──▶ Part 2 중복 제거·선별 ──▶ Part 3 질문에 답하는 챗봇
```

| 회차 | 날짜 | 핵심 질문 | 하는 일 | 결과물 |
|---|---|---|---|---|
| [Part 1](part1/) | 11/27 (금) | 무엇이 쓰레기인가? | 메일마다 사람이 쓴 글만 남기고, 내용 없는 메일과 광고를 버린다 | 깨끗한 메일 파일, 전처리 Skill |
| Part 2 | 12/2 (수) | 같은 내용이 몇 번이나 필요한가? 좋은 메일을 기계가 골라낼 수 있나? | 중복 메일을 지우고, 모델로 쓸모 있는 메일을 고른다 | 더 작고 알찬 메일 묶음 |
| Part 3 | 12/4 (금) | 다듬은 데이터가 정말 쓸모 있나? | Claude Code를 이 메일함 전문 질의응답 도우미로 만든다 | 근거와 함께 답하는 챗봇 |

앞 회차의 결과물이 다음 회차의 입력입니다. 수업에 빠졌거나 뒤처져도 정답 결과물을 받아 다음 단계부터 이어서 할 수 있습니다.

### 이것은 LLM을 만드는 방법과 같다

ChatGPT나 Claude 같은 LLM(대규모 언어 모델)은 인터넷 글 수십억 페이지로 학습합니다.
인터넷 글도 메일함처럼 지저분해서 그대로는 쓰지 못하고, 아래 순서로 다듬습니다.
우리는 웹 대신 메일함으로 **같은 과정을 작게** 해 봅니다.

| LLM 학습 데이터 (웹) | 우리 실습 (메일함) | 회차 |
|---|---|---|
| 웹 페이지(HTML)에서 글만 꺼내기 | 메일 원문을 날짜·보낸 사람·제목·본문으로 나누기 | Part 1 |
| 메뉴·광고 같은 쓸모없는 줄 지우기 (C4) | 이전 메일 인용, 면책 문구 지우기 | Part 1 |
| 품질 낮은 문서 통째로 버리기 (Gopher) | 내용 없는 메일, 광고 버리기 | Part 1 |
| 똑같거나 거의 같은 문서 지우기 | 폴더 사본, 비슷한 메일 지우기 | Part 2 |
| 모델로 좋은 글 고르기 (FineWeb-Edu) | 업무에 쓸모 있는 메일 고르기 | Part 2 |
| 다듬은 글로 모델 학습 | 다듬은 메일로 질문에 답하기 | Part 3 |

괄호 안의 이름은 실제 LLM 학습 데이터를 만든 사례입니다. 수업에서 하나씩 소개합니다.

### 여러분이 할 일

코드는 Claude Code가 작성합니다. 여러분이 할 일은 **무엇을 시킬지 정하고, 결과가 맞는지 확인하고, 왜 그런지 설명하는 것**입니다.

매 단계 교수자의 정답과 내 결과를 비교합니다. 숫자가 달라도 괜찮습니다.
어디가 왜 다른지 메일을 열어 보고 설명할 수 있으면 됩니다. 실습은 평가하지 않습니다.

## 준비 (수업 전에 한 번)

1. 저장소 받기
   ```
   git clone https://github.com/HAICoLab/dai2026-data-pipeline.git
   cd dai2026-data-pipeline
   ```
2. 패키지 설치
   ```
   pip install -r requirements.txt
   ```
3. 환경 점검. 모든 줄이 `[OK]`로 나오면 됩니다.
   ```
   python check_env.py
   ```
   (Mac에서 `python`이 없다고 나오면 `python3`, `pip3`로 바꿔 입력하세요.)

## 매 수업 시작할 때

```
cd dai2026-data-pipeline
git pull
claude
```

- Claude Code는 항상 이 폴더(저장소 루트)에서 실행합니다.
- 실습 중에 `git commit`이나 `git push`는 하지 않습니다. 내 결과물은 내 컴퓨터에만 둡니다.
- `git pull`이 실패하면 [문제 해결](#문제-해결)을 보세요.

## 폴더 구조

```
dai2026-data-pipeline/
├── CLAUDE.md            Claude Code가 지켜야 할 규칙과 파일 약속
├── check_env.py         환경 점검
├── data/raw/            원본 메일함 (수정 금지)
├── prep/                교수자가 데이터를 준비할 때 쓴 스크립트 (참고용)
├── part1/
│   ├── README.md        실습 순서와 Claude Code에 줄 요청 문구
│   ├── tests/           정규식 테스트
│   ├── solution/        교수자 정답 (결과, 비교 스크립트, Skill 예시. 정답 코드는 수업 후 공개)
│   ├── src/             내가 만든 스크립트 (실습하면서 생김)
│   └── out/             내 결과물 (실습하면서 생김)
└── .claude/skills/      내가 저장한 Skill (실습하면서 생김)
```

## 데이터에 대하여

- 출처: [CMU Enron Email Dataset](https://www.cs.cmu.edu/~enron/) (2015년 5월 7일 판). 엔론은 2001년 말 회계 부정으로 파산했고, 그 조사 과정에서 직원 약 150명의 회사 메일 약 50만 통이 공개되었습니다. 지금은 연구용 공개 데이터로 널리 쓰입니다.
- 이 저장소에는 그중 Kim Ward 한 사람의 메일함(`data/raw/ward-k.jsonl`)만 들어 있습니다. 메일 원문은 바꾸지 않았고, Windows에서도 받을 수 있도록 파일 하나로 묶기만 했습니다. 파일의 한 줄이 메일 한 통입니다.
- **실존 인물의 메일입니다.** 대부분은 사건과 무관한 평범한 직원들입니다. 수업 목적으로만 사용하고, 메일 내용이나 개인 정보를 수업 밖으로 옮기지 마세요.
- CMU는 2026년 4월, 당시 엔론 메일 시스템에 다른 사람을 사칭할 수 있는 결함이 있었다는 보고가 있다고 공지했습니다. 데이터를 쓸 때는 출처와 신뢰성을 항상 함께 확인해야 한다는 좋은 예입니다.

## 문제 해결

| 증상 | 해결 |
|---|---|
| `git pull`이 "local changes would be overwritten"으로 실패 | 교수자 파일을 수정한 경우입니다. `git stash` → `git pull` → `git stash pop` |
| 수업 중 뒤처졌을 때 | 각 Part의 README에 있는 "따라잡기" 명령으로 정답 결과를 복사해 다음 단계부터 합류합니다 |
| 한글이 깨져 보임 (Windows) | 파일을 열 때 `encoding="utf-8"`을 지정했는지 Claude Code에 확인을 요청하세요 |
| Claude Code 사용량 한도에 걸림 | 옆 사람과 함께 진행하고, 정답 결과로 다음 단계를 확인합니다 |
