# data-profiling: 메일함 진단

## 언제 쓰나
- 새 메일함을 받았고, 아직 아무것도 고치지 않았을 때
- 전처리 규칙을 정하기 전에 근거가 되는 숫자가 필요할 때

## 입력과 출력
- 입력: 메일함 JSONL (`id`, `folder`, `raw`)
- 출력: `<out-dir>/profile.json`, 그리고 `make_report.py`가 만드는 `<out-dir>/report.html`의 "S0 진단" 구역

## 단계
1. 진단 스크립트를 실행한다. 입력과 출력 폴더는 항상 직접 지정한다.
   ```
   python ${CLAUDE_SKILL_DIR}/scripts/s0_profile.py --input data/raw/<메일함>.jsonl --out-dir <out-dir>
   python ${CLAUDE_SKILL_DIR}/scripts/make_report.py --out-dir <out-dir>
   ```
2. 결과에서 다음 세 가지를 읽고 사용자에게 요약한다.
   - 여러 메일에 반복되는 줄 상위 30: 기계가 붙였거나 딸려 온 글의 후보
   - 특수 문자열 빈도: 인용, 전달, 인코딩 잔재, HTML이 얼마나 있는지
   - 길이 분포: 너무 짧거나 너무 긴 메일
3. 발견한 문제를 "문제 / 근거 숫자 / 제안하는 처리 / 처리 단계(S1·S2·S3)" 표로 정리한다.
4. 메일을 직접 확인할 때는 한 번에 5통 이하만 출력한다.

## 결정과 기준
- 반복 줄은 "그 줄이 들어 있는 메일 수"로 센다. 한 메일 안에서 여러 번 나와도 1번이다.
- 4글자 미만의 줄은 세지 않는다.
- 본문은 원문의 첫 빈 줄 다음부터로 본다. 이 단계에서는 디코딩도 정리도 하지 않는다.
- 소문자화, 불용어 제거, 어간 추출은 제안하지 않는다. 사람이 읽고 LLM이 읽을 글에서는 정보를 잃을 뿐이다.

## 검증 방법
- 보고한 숫자마다 실제 메일 2~3통을 열어 그 문자열이 정말 그런 뜻인지 확인한다.
- 메일 수가 입력 파일의 줄 수와 같은지 확인한다.

## 알려진 한계
- 특수 문자열 목록은 Enron 메일(Outlook, Lotus Notes)에 맞춘 것이다. 다른 출처의 메일은 목록을 고쳐야 한다.
- `=`로 끝나는 줄에는 인코딩 잔재뿐 아니라 `=====` 구분선도 들어 있다. 숫자를 그대로 믿지 않는다.
- 영어 메일 기준이다.
